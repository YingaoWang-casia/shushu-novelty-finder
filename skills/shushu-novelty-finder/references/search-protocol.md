# Search Protocol

Search only after the scope is clear enough.

## Source priority

1. Top conference or journal papers in the relevant CS subfield.
2. Highly relevant accepted papers from adjacent venues.
3. Surveys, benchmark papers, and dataset papers.
4. High-quality preprints, clearly marked as preprints.
5. Code repositories, project pages, and blog posts only as implementation evidence, not main literature evidence.

## Search directions

For a seed paper, search three lines:

- prior work: what the paper builds on;
- follow-up work: papers that cite, extend, or challenge it;
- sibling work: papers solving similar tasks around the same time.

For a broad direction, search by:

- task keywords;
- dataset names;
- metric names;
- method names;
- venue plus year;
- survey plus benchmark terms.

## Time slicing

When reviewing roughly 10 years of work, split the timeline:

- early stage: task definition and classical baselines;
- middle stage: deep learning or benchmark consolidation;
- recent stage: large-model, system, or deployment shift;
- latest stage: unstable but promising preprints and new benchmarks.

The exact years depend on the field.

## Anti-hallucination rule

If a paper cannot be verified by source, title, year, or venue, do not use it as evidence.
